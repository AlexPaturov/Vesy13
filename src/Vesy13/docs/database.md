# База данных

## PostgreSQL: локальная база

Локальная база используется для хранения калибровки, временного журнала
взвешиваний и аудита.

Фактическое подключение сейчас находится в коде `LocalRepository` и
`AuditLogger`.

### `wagon_weighing`

Хранит результаты потележечного взвешивания до и после переноса.

| Поле | Назначение |
| --- | --- |
| `id` | первичный ключ |
| `train_time` | время начала состава |
| `wagon_time` | время фиксации вагона |
| `wagon_num` | порядковый номер вагона в составе |
| `bogie1` | вес первой тележки, т |
| `bogie2` | вес второй тележки, т |
| `total` | общий вес, т |
| `direction` | направление для динамического режима |
| `mode` | `СТАТИКА` или `ДИНАМИКА` |
| `transferred` | признак переноса в Firebird |
| `when_insert` | время вставки |

### `calibration_points`

Хранит статическую калибровку по каналам.

| Поле | Назначение |
| --- | --- |
| `id` | первичный ключ |
| `channel` | канал АЦП: `0` или `1` |
| `adc_code` | код АЦП |
| `mass` | масса в тоннах |
| `calibration_value` | калибровочное число статической точки (`NUMERIC(12,3)`) |
| `is_active` | участвует ли точка в расчете |
| `created_at` | время добавления точки |
| `deleted_at` | время, когда точка стала неактивной |

Среди активных точек одного канала уникальны и масса, и код АЦП. Неактивные точки могут
повторять эти значения: они остаются в истории и не участвуют в ограничениях.

Статическое взвешивание использует сохраненное `calibration_value`:
`вес = (код АЦП - код нулевой точки) * calibration_value / 65535`.

При сохранении точек неактивные записи не удаляются физически: им выставляется
`deleted_at`. Несколько активных точек на канал — штатная ситуация, нужны для
расчета по точкам перелома.

### `direction_correction_profiles`

Хранит историю коэффициентов динамического режима.

| Поле | Назначение |
| --- | --- |
| `id` | первичный ключ |
| `right_direction_correction_factor` | коэффициент для направления `→`; `0` — валидное значение |
| `left_direction_correction_factor` | коэффициент для направления `←`; `0` — валидное значение |
| `is_active` | признак текущей активной строки |
| `created_at` | время добавления строки |
| `deleted_at` | время, когда точка стала неактивной |

Активная строка определяется условием `is_active = TRUE AND deleted_at IS NULL`.
При сохранении новых коэффициентов (`LocalRepository.SaveDirectionCorrectionProfileAsync`) старая
активная строка снимается (`is_active = FALSE`, `deleted_at = NOW()`), а новая
вставляется как активная — история всех прежних значений сохраняется, не только
последнее.

### `audit_log`

Хранит события приложения и ошибки:

- открытие форм;
- сохранение взвешивания;
- перенос и корректировки;
- генерация отвесной;
- сохранение настроек и калибровки;
- подключение/ошибки АЦП;
- ошибки БД/PDF/общие ошибки.

`LogsForm` читает до 5000 записей за выбранный период и поддерживает экспорт в
CSV.

Словарь полей:

| Поле | Назначение и источник |
| --- | --- |
| `id` | Технический идентификатор записи (`BIGSERIAL`). |
| `time_created` | Время события в UTC; задаётся приложением до помещения записи в очередь аудита. |
| `event_id` | Код события из констант `AuditLogger`: 1000 — действия формы и данные, 2000 — АЦП/настройки, 9000 — ошибки. |
| `keywords` | Результат события: `Audit Success` для штатного действия, `Audit Failure` для ошибки. |
| `computer` | Имя компьютера, на котором работает приложение. |
| `subject_user_sid` | SID интерактивного пользователя Windows. |
| `subject_user_name` | Имя интерактивного пользователя Windows без домена. |
| `subject_domain_name` | Домен пользователя Windows или имя рабочей группы. |
| `subject_logon_id` | Windows Logon ID сеанса; позволяет различить сеансы одного пользователя. |
| `object_server` | Подсистема или внешний ресурс события: например, `PostgreSQL`, `Firebird`, `QuestPDF`, `Vesy13`. |
| `object_type` | Тип объекта либо операция: например, `LocalWagon`, `AdcConnection`, `WeighingSlip`. |
| `object_name` | Читаемое описание объекта или операции: номер вагона, имя таблицы, параметры действия. |
| `object_handle` | Короткий дополнительный идентификатор: ID записи, имя COM-порта, путь к сформированному файлу. Может быть `NULL`. |
| `process_id` | PID процесса Vesy13. |
| `process_name` | Полный путь к исполняемому файлу процесса. |
| `workstation_name` | Имя рабочей станции; в текущей реализации дублирует `computer` для совместимости с форматом аудита. |
| `ip_address` | Первый найденный IPv4-адрес рабочей станции. Может быть `NULL`. |

`AuditLogger.Exception` использует те же поля без миграции схемы: `object_server` — подсистема, `object_type` — операция или тип объекта, `object_handle` — короткий идентификатор, а в `object_name` помещаются контекст и полный `Exception.ToString()`.

Если PostgreSQL недоступна, только запись исключения сохраняется в UTF-8 файл `%ProgramData%\Vesy13\logs\audit-exceptions-YYYY-MM-DD.log`. Формат — читаемый блок с UTC-временем, `event_id`, контекстными полями и `Exception.ToString()`; обычные события аудита в файл не дублируются. Файлы хранятся 30 дней и удаляются при очередной аварийной записи.

## Очистка локальных данных

Очистку выполняет само приложение; внешнего задания Windows и отдельного `purge.sql`
нет. Проверка запускается один раз после показа главного окна.

- При первом запуске в `settings.json` сохраняется текущая дата как начало периода.
  В этот момент данные не удаляются.
- Начиная с 60-го дня периода программа удаляет в одной транзакции записи из
  `wagon_weighing` по `when_insert` и из `audit_log` по `time_created`, если они
  старше 30 дней. История калибровки и коэффициентов направления не очищается.
- Перед попыткой сохраняется её дата. При ошибке повторная попытка в тот же
  календарный день не выполняется; следующая выполняется при первом запуске
  программы в следующий день, пока очистка не завершится успешно.
- После успешной очистки текущая дата становится началом нового 60-дневного периода.
  При недоступности базы срок хранения может превысить 60 дней до успешной попытки.

Успешная очистка и её ошибка регистрируются в аудите как операция `DatabaseCleanup`.

## Firebird: заводская база

`FactoryRepository` работает с таблицами:

- `GPRI` - приход;
- `GRAS` - расход.

Основные операции:

- `InsertAsync` - вставляет перенесенную локальную запись.
- `UpdateAsync` - обновляет существующую запись.
- `GetRecentAsync` - читает последние записи из обеих таблиц.
- `GetByTrainTimeAsync` и `GetByDateAsync` - ищут записи по времени состава или дате.
- `GetForPrintAsync` - выбирает записи для отвесной по фильтрам.
- `GetTaraOptionsAsync` - получает варианты тары за последний год по номеру вагона.

## Сопоставление локальной записи и Firebird

При переносе из `LocalWagon` создается `GpriGras`:

| Firebird поле | Источник |
| --- | --- |
| `Table` | выбор оператора: `GPRI` или `GRAS` |
| `DT` | дата `WagonTime` |
| `VR` | время `TrainTime` |
| `VR_PRV` | время `WagonTime` |
| `NVAG` | номер вагона, введенный оператором |
| `NPP` | `LocalWagon.Number` |
| `REJVZVESH` | режим взвешивания |
| `BRUTTO` | общий вес, если это брутто |
| `TAR_BRS` | общий вес, если это тара |
| `NETTO` | `BRUTTO - TAR_BRS`, если выбрана тара |
| `GRUZ`, `POTR`, `PLAT`, `CEX` | реквизиты из формы корректировок |

После успешной вставки в Firebird локальная запись помечается
`transferred = true`.
