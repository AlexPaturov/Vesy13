# Отчёт о выполненных работах

Документ ведётся в хронологическом порядке. Новые пункты следует добавлять в конец,
сохраняя нумерацию.

## 1. Перенос рабочих настроек

**Проблема.** Оператор без прав администратора не мог сохранять настройки, если
они находились рядом с программой. Это затрагивало настройки, пароль администратора
и кэш калибровки.

**Выполненное решение.** Настройки перенесены в общий каталог данных. При первом
запуске программа переносит ранее сохранённые настройки. Права на каталог настроены
для работы оператора.

**Результат.** Настройки, пароль администратора и кэш калибровки сохраняются при
работе программы и при обновлении.

## 2. Подготовка самостоятельных пакетов развёртывания

**Проблема.** Требовалась независимая установка программы и локальной базы данных.

**Выполненное решение.** Подготовлены два самостоятельных установочных комплекта:

- для программы;
- для локальной базы данных.

Комплект программы выполняет публикацию, установку, создание ярлыка и подготовку
каталога рабочих данных. Комплект базы данных выполняет установку, настройку и
создание структуры базы.

**Результат.** Программу и базу данных можно передавать и устанавливать независимо.

## 3. Регистрация ошибок в журнале

**Проблема.** Ошибки при записи журнала могли не сохраняться.

**Выполненное решение.**

- Добавлена запись полного текста ошибки в журнал.
- Добавлено сохранение ошибки в отдельный файл, если запись в базу данных невозможна.
- Добавлена регистрация необработанных ошибок программы.
- Добавлена автоматическая очистка файлов с ошибками старше 30 дней.

**Трудности и контроль.** При доработке были выявлены и исправлены ошибки в местах
вызова журнала. Отдельно определён порядок записи при недоступности базы данных,
чтобы одна и та же ошибка не записывалась повторно.

**Результат.** Ошибки сохраняются как при доступной, так и при недоступной базе
данных.

## 4. Проверка настройки доступа к локальной базе данных

**Проблема.** При проверке журнала обнаружено, что локальная база данных запрашивала
пароль, хотя для программы предусмотрено подключение без пароля.

**Выполненное решение.** Повторно выполнена штатная настройка базы данных. Она
настроила разрешённое локальное подключение программы без пароля.

**Результат.** Подключение программы к локальной базе данных работает без пароля;
новый механизм регистрации ошибок подтвердил работоспособность при проверке.

## 5. Корректность журнала и сообщений об ошибках

**Проблема.** В журнале требовалось точно различать успешные действия, отклонённые
операции и ошибки. В отдельных случаях пользователю мог выводиться технический текст
ошибки.

**Выполненное решение.** Исправлена классификация событий журнала. Добавлена
регистрация внутренней ошибки самого механизма журнала. Технические сведения об
ошибках исключены из сообщений для оператора.

**Результат.** Журнал достовернее отражает исход операций, а оператор получает
понятное сообщение без служебных подробностей.

## 6. Регистрация событий форм и состояния связи

**Проблема.** В журнале было невозможно однозначно определить открытие и закрытие
форм, а также изменение состояния связи с измерительным оборудованием.

**Выполненное решение.** Добавлена регистрация открытия и закрытия всех форм.
Добавлена регистрация установления, потери, восстановления и штатного закрытия
соединения с измерительным оборудованием на формах статического и динамического
взвешивания, а также обслуживания.

**Результат.** По журналу можно восстановить последовательность работы оператора и
состояние связи с оборудованием.

## 7. Сохранение истории статической калибровки

**Проблема.** Изменение калибровочной точки могло привести к потере её прежнего
значения.

**Выполненное решение.** Сохранённые точки сделаны неизменяемыми: новая точка
добавляется отдельной записью, а прежнюю можно только снять вручную. Для активных
точек одного канала введена проверка уникальности массы.

**Результат.** История калибровки сохраняется полностью, а одновременно действующие
точки не имеют повторяющейся массы.

## 8. Полный журнал изменений калибровки

**Проблема.** Запись о сохранении калибровки содержала только краткое сводное
сообщение и не позволяла установить точные изменённые значения.

**Выполненное решение.** Для каждой изменённой статической точки в журнал заносятся
все её поля после сохранения. Для динамической калибровки отдельно записываются
поля снятого прежнего профиля и добавленного нового профиля.

**Результат.** Журнал содержит точную историю изменений калибровки с возможностью
проверить каждое сохранённое значение.

## 9. Хранение калибровочного числа статической калибровки

**Проблема.** Калибровочное число статической точки раньше не хранилось как
отдельное значение. Оно рассчитывалось из массы и кода, поэтому оператор не мог
задать его вручную, а в журнале не было видно итоговое значение, по которому
выполняется расчёт.

**Выполненное решение.** Для статической калибровки добавлено отдельное обязательное
калибровочное число. Расчёт веса переведён на это сохранённое значение. На форме
добавлен режим ручного ввода: при отключении автоматического расчёта форма
визуально выделяется красным цветом, при включении автоматического расчёта
возвращается обычное оформление. В журнал изменения статической калибровки теперь
записывается калибровочное число вместе с остальными полями точки.

**Трудности и контроль.** Изменение затронуло не только форму, но и структуру базы
данных, загрузку и сохранение точек, расчёт веса, локальный кэш и журнал. Отдельно
сохранено правило уникальности массы среди активных точек.

**Результат.** Калибровочное число стало полноценной частью статической
калибровочной точки. Оператор может работать как с автоматическим расчётом, так и
с ручным вводом, а журнал содержит значение, реально участвующее в расчёте.
