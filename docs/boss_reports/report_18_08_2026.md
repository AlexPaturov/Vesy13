# Отчёт о выполненных работах

Документ ведётся в хронологическом порядке. Новые пункты следует добавлять в конец, сохраняя нумерацию.

## 1. Для программы и локальной базы данных требовалась независимая установка

Для этого подготовлены два самостоятельных установочных комплекта: отдельно для программы и отдельно для локальной базы данных.

Комплект программы выполняет публикацию, установку, создание ярлыка и подготовку каталога рабочих данных. Комплект базы данных выполняет установку, настройку и создание структуры базы. Программу и базу данных теперь можно передавать и устанавливать независимо друг от друга для windows 11.

## 7. Журнал изменений калибровки не позволял определить точные изменённые значения

Ранее при сохранении калибровки в журнал записывалось только краткое сводное сообщение. Чтобы обеспечить полную историю изменений, для каждой изменённой статической точки в журнал теперь записываются все её поля после сохранения.

Для поправочных коэффициентов направления отдельно регистрируются поля прежнего профиля, сделанного неактивным, и добавленного нового профиля. В результате по журналу можно проверить каждое сохранённое значение и восстановить точную историю изменений калибровки.

## 8. Калибровочное число статической точки не хранилось как самостоятельное значение

Ранее оно рассчитывалось из массы и кода, поэтому оператор не мог задать калибровочное число вручную, а в журнале отсутствовало итоговое значение, непосредственно участвующее в расчёте.

Чтобы устранить это ограничение, для статической калибровки добавлено отдельное обязательное калибровочное число, а расчёт веса переведён на его сохранённое значение. На форме реализован ручной ввод: при отключении автоматического расчёта форма визуально выделяется красным цветом, а при его включении возвращается обычное оформление. Калибровочное число также добавлено в журнал изменений статической калибровки вместе с остальными полями точки.

Доработка затронула структуру базы данных, загрузку и сохранение точек, расчёт веса, локальный кэш и журнал. При этом сохранены правила уникальности массы и кода АЦП среди активных точек. Оператор теперь может использовать как автоматический расчёт, так и ручной ввод, а в журнале сохраняется значение, которое фактически используется при расчёте веса.

## 9. Сервисная статическая калибровка содержала несколько неудобств и неиспользуемых элементов

Ввод массы с запятой мог отключать автоматический расчёт. Чтобы исключить зависимость от используемого десятичного разделителя, форма теперь принимает как запятую, так и точку. При ошибочном значении соответствующая ячейка выделяется и оператор получает пояснение, что необходимо исправить.

При отключённом АЦП оператор мог нажать «Захватить», но код не записывался в калибровочную точку и причина была неясна. Теперь кнопка недоступна, пока нет живого соединения с АЦП и актуального ненулевого кода.

Из статической калибровки также удалён блок расчёта методом наименьших квадратов. Мастер ремонта и эксплуатации сообщил, что этот расчёт им не нужен; блок не участвовал в рабочем взвешивании и только усложнял форму. В результате интерфейс содержит только используемые действия и даёт оператору понятную обратную связь при вводе данных и работе с оборудованием.

## 10. При правке проекта из разных сред появлялись технические изменения окончаний строк

Окончания `CRLF` в файлах WinForms Designer, ресурсах, проектах и установочных скриптах использовались намеренно. Проблема проявилась при правках из Linux-среды: такие инструменты записывают `LF`, а в репозитории не было правил, задающих формат для каждого типа файлов. Поэтому Git мог показать изменение всего файла, хотя его содержимое не менялось.

У разработчиков, работающих только в одной Windows-среде и не меняющих формат файлов, эта ситуация не возникает. В проект добавлены правила: обычный код и документация используют `LF`, а файлы WinForms Designer, ресурсы, проекты и установочные скрипты — `CRLF`. Существующие файлы приведены к этим правилам отдельной технической нормализацией.
