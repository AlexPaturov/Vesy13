# База данных

## PostgreSQL: локальная база

Локальная база используется для хранения калибровки, временного журнала
взвешиваний и аудита.

Фактическое подключение сейчас находится в коде `LocalRepository` и
`AuditLogger`.

### `wagon_weighing`

Хранит результаты потележечного взвешивания до и после переноса.

| Поле | Назначение |
| --- | --- |
| `id` | первичный ключ |
| `train_time` | время начала состава |
| `wagon_time` | время фиксации вагона |
| `wagon_num` | порядковый номер вагона в составе |
| `bogie1` | вес первой тележки, т |
| `bogie2` | вес второй тележки, т |
| `total` | общий вес, т |
| `direction` | направление для динамического режима |
| `mode` | `СТАТИКА` или `ДИНАМИКА` |
| `transferred` | признак переноса в Firebird |
| `when_insert` | время вставки |

### `calibration_points`

Хранит статическую калибровку по каналам.

| Поле | Назначение |
| --- | --- |
| `id` | первичный ключ |
| `channel` | канал АЦП: `0` или `1` |
| `adc_code` | код АЦП |
| `mass` | масса в тоннах |
| `is_active` | участвует ли точка в расчете |
| `created_at` | время добавления точки |
| `deleted_at` | мягкое удаление |

При сохранении точек неактивные записи не удаляются физически: им выставляется
`deleted_at`. Несколько активных точек на канал — штатная ситуация, нужны для
расчета по МНК/точкам перелома.

### `calibration_dynamic`

Хранит историю коэффициентов динамического режима.

| Поле | Назначение |
| --- | --- |
| `id` | первичный ключ |
| `k_plus` | коэффициент для направления `→`; `0` — валидное значение |
| `k_minus` | коэффициент для направления `←`; `0` — валидное значение |
| `is_active` | признак текущей активной строки |
| `created_at` | время добавления строки |
| `deleted_at` | время снятия строки |

Активная строка определяется условием `is_active = TRUE AND deleted_at IS NULL`.
При сохранении новых коэффициентов (`LocalRepository.SaveDynamicCalibAsync`) старая
активная строка снимается (`is_active = FALSE`, `deleted_at = NOW()`), а новая
вставляется как активная — история всех прежних значений сохраняется, не только
последнее.

### `audit_log`

Хранит события приложения и ошибки:

- открытие форм;
- сохранение взвешивания;
- перенос и корректировки;
- генерация отвесной;
- сохранение настроек и калибровки;
- подключение/ошибки АЦП;
- ошибки БД/PDF/общие ошибки.

`LogsForm` читает до 5000 записей за выбранный период и поддерживает экспорт в
CSV.

## Очистка данных

Глубина хранения — 30 дней. Задание pgAgent `vesy13_purge` (`install/purge_job.sql`)
запускается 1-го числа каждого месяца в 03:00 и удаляет строки старше этого срока:

| Таблица | Условие |
| --- | --- |
| `wagon_weighing` | `when_insert` старше 30 дней, при любом значении `transferred` |
| `audit_log` | `time_created` старше 30 дней |

Реальный возраст данных колеблется от 30 до 60 дней: сразу после прогона самой старой
записи 30 дней, накануне следующего — почти 60.

Взвешивание, не перенесённое в Firebird за этот срок, удаляется вместе с остальными —
решение владельца проекта. Календарь чистки `audit_log` совпадает, поэтому следа
удалённого взвешивания в журнале аудита к этому моменту тоже не остаётся.

Калибровочные таблицы `calibration_points` и `calibration_dynamic` хранят настройку
весов: активные точки живут годами и сохраняются на всё время эксплуатации.

pgAgent устанавливается отдельным компонентом (StackBuilder в дистрибутиве EDB),
работает службой Windows и хранит расписание в схеме `pgagent` — обычно в базе
`postgres`, откуда подключается к `scale_db` для выполнения шага.

## Firebird: заводская база

`FactoryRepository` работает с таблицами:

- `GPRI` - приход;
- `GRAS` - расход.

Основные операции:

- `InsertAsync` - вставляет перенесенную локальную запись.
- `UpdateAsync` - обновляет существующую запись.
- `GetRecentAsync` - читает последние записи из обеих таблиц.
- `GetByTrainTimeAsync` и `GetByDateAsync` - ищут записи по времени состава или дате.
- `GetForPrintAsync` - выбирает записи для отвесной по фильтрам.
- `GetTaraOptionsAsync` - получает варианты тары за последний год по номеру вагона.

## Сопоставление локальной записи и Firebird

При переносе из `LocalWagon` создается `GpriGras`:

| Firebird поле | Источник |
| --- | --- |
| `Table` | выбор оператора: `GPRI` или `GRAS` |
| `DT` | дата `WagonTime` |
| `VR` | время `TrainTime` |
| `VR_PRV` | время `WagonTime` |
| `NVAG` | номер вагона, введенный оператором |
| `NPP` | `LocalWagon.Number` |
| `REJVZVESH` | режим взвешивания |
| `BRUTTO` | общий вес, если это брутто |
| `TAR_BRS` | общий вес, если это тара |
| `NETTO` | `BRUTTO - TAR_BRS`, если выбрана тара |
| `GRUZ`, `POTR`, `PLAT`, `CEX` | реквизиты из формы корректировок |

После успешной вставки в Firebird локальная запись помечается
`transferred = true`.
