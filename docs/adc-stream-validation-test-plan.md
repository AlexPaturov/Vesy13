# План тестирования валидации динамического потока АЦП

## Цель

Покрыть автоматическими тестами проверку 5-байтных динамических кадров SIM A04
и восстановление синхронизации при мусоре, повреждённых данных и частичном
поступлении потока. Тесты не должны требовать подключённого АЦП, COM-порта или
WinForms.

## 1. Выделить протокольный код

1. Создать библиотеку `ADCProtocol` с целевой платформой `net6.0`.
2. Разместить в ней:
   - модель 5-байтного динамического кадра;
   - проверку контрольной суммы;
   - потоковый декодер, принимающий последовательность байтов.
3. Закрепить единую формулу проверки:

   ```text
   AUX = (B0 + B1 + B2 + B3) & 0xFF
   ```

4. При неверной сумме декодер должен сдвигать окно на один байт и продолжать
   поиск следующего кадра.

## 2. Создать проект тестов

1. Создать `ADCProtocol.Tests` с целевой платформой `net6.0`.
2. Подключить пакеты:
   - `Microsoft.NET.Test.Sdk`;
   - `MSTest.TestFramework`;
   - `MSTest.TestAdapter`.
3. Добавить проект в `Vesy13.sln`.

Выбран MSTest, так как это официальный тестовый стек Microsoft: он без
дополнительной инфраструктуры поддерживается Visual Studio Test Explorer и
запускается командой `dotnet test`. Целевая платформа `net6.0` позволяет
выполнять алгоритмические тесты на Windows и Linux.

## 3. Тесты отдельного динамического кадра

Написать пять сценариев.

1. Корректный кадр принимается.
2. Кадр с неверным пятым байтом отклоняется.
3. Изменение каждого из четырёх байтов данных делает кадр неверным.
4. Переполнение суммы корректно обрабатывается по модулю 256.
5. `CH0` и `CH1` правильно собираются из байтов в порядке little-endian.

## 4. Тесты потокового декодера

Написать шесть сценариев.

1. Целый корректный кадр выдаётся декодером.
2. Кадр, пришедший несколькими порциями, выдаётся только после получения
   пятого байта.
3. Мусорные байты перед кадром пропускаются, следующий корректный кадр
   находится.
4. После неверного 5-байтного кандидата декодер сдвигает окно на один байт и
   находит следующий корректный кадр.
5. Два корректных кадра подряд выдаются в исходном порядке.
6. Несколько повреждённых фрагментов не блокируют поток: следующий корректный
   кадр находится, а счётчик отклонённых кандидатов увеличивается.

Итого — 11 сценариев. Параметризованные варианты допустимы, но в отчёте тестов
должны быть понятны все перечисленные случаи.

## 5. Подключить декодер к приложениям

1. Перевести `SimA04ReaderDynamic` на новый потоковый декодер.
2. Сохранить существующие события успешного кадра и отклонённой контрольной
   суммы.
3. Убрать дублирование формулы из `DynamicDumpDec` и `ScaleListener`: они
   должны использовать протокольную библиотеку или единую её функцию суммы.
4. Оформить перенос протокольной логики и переход потребителей разными
   смысловыми коммитами.

## 6. Запуск и критерии готовности

Запуск всех тестов:

```powershell
dotnet test ADCProtocol.Tests/ADCProtocol.Tests.csproj
```

Запуск отдельного сценария:

```powershell
dotnet test ADCProtocol.Tests/ADCProtocol.Tests.csproj --filter "FullyQualifiedName~<ИмяТеста>"
```

Также все тесты должны быть доступны в Visual Studio через **Test Explorer**.

Критерий готовности: все 11 сценариев проходят. Обязательный контрольный
случай — повреждённый или несинхронизированный первый кадр, за которым следует
корректный: декодер обязан найти второй кадр без перезапуска считывания.
